# 问津 RAG 管理界面

管理界面由文件管理 HTTP 服务同源提供，使用原生 HTML、CSS 和 JavaScript，无 CDN、外部字体或 Node 构建服务。浏览器负责展示与提交请求，文件管理服务负责持久任务、活动版本和资源清理；MCP 仍只提供授权后的读取。

## 启动与连接

从项目根目录运行：

```powershell
uv run python -m wenjin.file_management serve --host 127.0.0.1 --port 8777
```

打开 `http://127.0.0.1:8777/admin/`。已有文件管理服务时直接使用该进程，不能对相同 root 启动第二个管理器。服务启用 `WENJIN_FILE_ADMIN_TOKEN` 时，在页面的连接设置中输入对应 Bearer；本机未设置 token 时可留空连接。不要把实际 token 写入文档、截图或 URL。

当前服务保留两种互斥认证模式。旧模式不传 `--identity-db`，继续使用原管理 Bearer 合同；本地账号模式显式传入独立SQLite身份库，启用会话登录、admin/reader角色、资料库读取授权、个人MCP凭据和身份审计。账号模式不把旧管理token当作日常旁路，也不自动迁移旧 `*` ACL 或授予既有资料库。页面凭据只在当前页面内存使用；MCP token创建时只展示一次。远程使用仍须由部署者配置可信TLS边界，不代表已完成企业SSO或生产部署。

## 本地账号初始化与使用

在项目根目录以同一身份库路径先初始化首位管理员，再启动管理服务。首位管理员密码由 `getpass` 交互输入，不进入命令行历史：

```powershell
uv run python -m wenjin.file_management bootstrap-admin `
  --identity-db .\data\identity.sqlite --username admin

uv run python -m wenjin.file_management serve `
  --root . --identity-db .\data\identity.sqlite `
  --host 127.0.0.1 --port 8777
```

然后打开 `http://127.0.0.1:8777/admin/`，用刚创建的管理员登录。CLI初始化会检查身份库为空并原子创建第一位管理员；`serve` 的 `--identity-db` 必须指向同一文件。浏览器在零用户状态会给出同机CLI引导。按2026-10-12用户确认的新规则，活动管理员可读取所有当前有效资料库，不需给自己逐库授权；普通账号仍须显式授权。管理员也不能绕过失效索引、版本准入、账号停用或首次改密限制。

管理员可在身份与授权页创建 `reader` 或 `admin` 用户、设置临时密码、启停账户、重置密码、授予/撤销具体资料库读取权并查看审计。新普通用户默认零库权限；管理员按角色读取所有有效资料库。reader登录后只能访问已授权资料库的检索和原文；撤权或停用在下一请求立即生效。reader可在身份页修改密码并创建/撤销自己的MCP个人凭据；token用途与网页登录会话隔离。

资料库授权默认一库一行，显示已授权普通用户人数。展开后勾选允许读取的普通用户，取消勾选表示撤销，点击“保存修改”只提交变更；取消恢复当前已读取的初始值。管理员不参与逐库授权编辑，保留其角色读取能力和历史grant。停用用户不能新增授权，可撤销既有授权；缺失账号记录不会自动删除。保存仍逐项校验revision，部分失败会重新读取服务端状态并说明结果，不保证整批原子提交。

会话期限按账号库策略显示。当前默认空闲期限为30分钟、绝对期限为12小时；认证请求会更新空闲计时，页面后台刷新可能延长空闲期，但不会延长12小时绝对上限。成功修改密码会撤销该用户现有网页登录会话和MCP凭据，随后需要重新登录。当前页授予读取权限后会刷新检索资料库选项；其他已登录用户回到页面、切换检索页或重新展开资料库选择时会刷新自己的授权目录。撤权后相关选择和旧检索证据会清除。

MCP服务也必须指向同一身份库：

```powershell
uv run python -m wenjin.mcp_server `
  --identity-db .\data\identity.sqlite --host 127.0.0.1 --port 8765
```

用户完成首次改密后，可在身份页管理自己的MCP凭据；管理员可在同一凭据区选择所属用户，查询、签发与撤销该用户的凭据。用户列表中的凭据入口只切换到对应用户，不会自动签发或撤销。填写便于识别的名称和有效期，签发成功后复制一次完整凭据，通过可信渠道交给所属用户，由其配置Agent的Bearer认证；客户端MCP服务地址以部署配置为准，不能把管理页地址当作MCP地址。

数据库只保存凭据哈希和安全前缀，日后只能查看名称、前缀、所属用户、状态及时间，不能恢复完整token。遗失时签发新凭据并撤销旧凭据；旧凭据不会因签发新凭据自动失效。一次交付区提供复制、手动选择及隐藏清除，切换用户/账号或退出清除原文；凭据不会保存到URL、localStorage或日志。创建、到期、撤销时间固定显示北京时间（Asia/Shanghai），不取浏览器本地时区；已过期、已撤销与账号不可用明确区分。不自动过期不等于永远可用：停用账号、改密或撤销仍使其失效。网页登录会话期限单独展示，不等于MCP凭据有效期。

凭据属于使用账号，按该账号当前角色和资料库授权读取；管理员为普通账号代签发不会赋予管理员权限，也不会自动授权资料库。不要把管理员自己的token发给其他人共用，或把token写入项目文档、截图、共享命令历史。旧管理Bearer不会在账号模式转化成MCP身份；MCP仍使用 `2025-11-25` 的 `initialize` / `notifications/initialized` 状态化会话，身份按每次请求重新解析。

## 页面与操作

顶栏账户菜单显示当前用户名、角色和会话期限，所有业务页面均可进入“切换账号”或“退出登录”。两者发出会话撤销请求时立即清空当前页面的凭据、选择与证据，随后打开登录窗口；旧请求不能回填新账号页面。旧Bearer模式显示“连接设置”和“断开连接”，不将管理token称为个人账号。页面无需保存凭据到URL或浏览器持久存储。

| 页面 | 当前操作 | 数据与边界 |
|---|---|---|
| 概览 | 文件、受管/历史文件、片段统计，跳转常用操作 | 来自本次文件清单；不代表整套 RAG/MCP、模型或 Qdrant 健康检查 |
| 文件管理 | 资料库折叠分组、分类标签、筛选、上传、详情、资源对账、下载、替换、删除、创建可管理副本 | 已有资料只读展示与检索；分类不改变权限，替换、删除仅作用于受管文件 |
| 任务中心 | 历史任务分页、按 ID 查询、进度与原因、失败重试 | 从服务持久 jobs 表读取，包含替换和删除历史；不只是当前浏览器提交的任务 |
| 检索调试 | 选择资料库、版本来源、可选文档，设置 Top K 与证据正文预算 | `/api/admin/search`；既有共享库只读检索和受管文件检索，不生成答案 |
| 调用日志 | 调用类型、状态、目标筛选与分页 | 管理 HTTP 请求元数据 + 可读取的 MCP 检索/取件审计；不是全部 MCP 工具日志 |
| 身份与授权 | 本地用户、角色、密码重置、资料库读取授权、个人MCP token和身份审计 | 账号模式可用；管理员可读所有有效库，普通账号按逐库授权 |
| 资料库版本 | 查看发布版本、校验、切换与回退 | 管理员API基于固定release；reader普通检索仅读取active版本 |
| 检索评测 | 提交白名单GDAL单题诊断或开发集四臂评测，查看阶段/进度/结果/审计 | 管理员专有；仅固定开发题集，不能提交脚本、路径或自定义题集；冻结test不运行 |
| 能力/迭代路线 | 查看已实现能力和下一步 | 按账号权限动态显示；代码存在不等于当前服务进程已经部署或完成生产验收 |

上传与替换使用原始文件 bytes，请求头 `X-File-Name` 使用百分号编码。文件格式能否解析仍以服务实际支持和任务结果为准；页面不会把“已选择文件”或 HTTP 202 写成“入库成功”。上传大小上限从受保护的 `/api/admin/config` 获取。任务最终状态由服务返回。

任务筛选和统计针对当前分页；按完整任务 ID 可直接查询。列表省略资源明细，详情可展开完整资源 JSON。删除会清理版本登记，相关历史任务的版本可能显示为空；界面不从当前文件版本推测历史版本。

已有资料库按稳定资料库身份归组，组内区分语料版本与受管文件版本。折叠仅改变展示；上传指定的归属也是逻辑归属，不合并原文或索引。文件搜索命中时自动展开相应分组，点击文档查看详情。文件页可按资料库类型（公开资料/私有资料）、状态和文档类型筛选，三个默认选项均显示“全部”；资料库类型使用分类标签，不影响权限。系统默认的“受管文件”归属组没有文档时不展示，有文件或未就绪任务时继续展示；主动创建的空资料库保留。来源信息仍在版本分组与详情中显示。

共享资料不自动转成受管文件。目录中的“可检索”与“支持替换、删除”是独立能力；没有通过资产检查或不在检索范围的文件会显示不可检索。“创建可管理副本”会校验并复制原文，再构建独立受管索引；原共享文件、manifest、索引和路由继续保留。只有需要通过管理页面独立替换或删除时才使用，正常检索旧资料不需要复制。复制不授予读取权限。删除只清理管理器登记的受管资源和历史版本，不清理共享原资产、外部备份或历史 artifacts。

私域共享资料的旧版服务选择仅认有效schema1路由声明中的唯一索引目标；独立目标配置只算候选，不能自动登记为可授权资源。多个目标、冲突声明或失效索引显示尚未发布/需检查。已迁入release的资料库仍服从活动发布指针，指针失效不回退旧配置。管理员可发现元数据并读取当前有效来源；普通账号及其MCP目录只展示获准读取的活动资料。目录同步不生成任何普通用户授权记录。普通账号撤权后清空旧证据并拒绝新读取请求；管理员身份仍按角色读取，若要移除该能力须停用账号或改变角色。

资料库分组中的“公开资料 / 私有资料”是分类标签。管理员可通过 `GET/PUT /api/admin/libraries/{library_id}/classification` 查看/修改，PUT传`classification`和`expected_revision`，冲突返回409。标签按稳定library_id单独存储并审计；不改原manifest、来源属性、发布状态或用户授权。首次未保存时依据来源给出默认分类，revision为0。身份库从v1升级到v2仅增加分类表，不修改用户或grants。来源公开/私域与分类标签相互独立；将标签设为公开不允许未获授权的普通账号读取，将标签设为私有也不撤销已有授权。

这里的MCP目录/权限检查指管理服务的 `/api/mcp/*` 桥。当前原生MCP `search_docs`默认路由仍不自动加载尚未进入release的私域目标；管理目录可授权、管理检索可用，不代表Agent工具已完成该私域库的路由接线。此项须单独接入并验证真实客户端，重启服务不能替代接线。

## 预算与版本

“证据正文预算（字符）”限制返回证据正文的总字符数，按 Python `len(text)` 累计，不是 Token 数，也不是模型上下文窗口。系统保留完整片段，超出剩余预算的片段会跳过，因此最终数量可能少于 Top K。默认 8000 沿用后端配置；本轮没有对照实验证明它是最优值，也没有调整检索参数或选择器。

页面默认检索当前生效版本。文件清单中的文件身份、资料库归属、状态或活动版本发生变化时，页面会同步刷新检索资料库与版本选项，并保留仍有效的当前选择；任务轮询只在这些目录字段变化时扫描共享资料库，不因进度或更新时间变化重复扫描。目录刷新失败会提示错误、保留待同步状态并延迟重试一次；后续文件清单轮询也会重试。受管检索把页面取得的唯一 `version_id` 发回服务端，在与版本切换共用的锁内校验，解决只比较版本名称时无法识别同名替换的问题。共享资料检索绑定具体索引目标、manifest、当前原文字节、BM25 和完整向量/payload 快照，检索前后都复核身份和当前路由；限定文档在关键词与向量候选召回前生效。过期请求返回冲突提示，页面清空旧证据并刷新清单。

共享目录的快速状态与短时缓存不替代搜索时的完整准入。余弦向量先归一化方向并量化到小数点后7位，避免本地Qdrant查询重归一化的浮点抖动；这不是向量字节身份，低于量化精度的方向变化可能不改变指纹，DOT/Euclid保留原值。当前完整快照需要扫描资产，成本随资料库增长；未来应由统一发布流程提供不可变资产和发布代号。检索前后检查不能替代外部写入方的事务或跨进程锁，外部直接改写资产仍应避免。

## 调用日志覆盖与隐私

任务中心保存导入、替换、删除和重试等后台作业。调用日志记录请求时间、调用类型、目标、耗时、状态、安全错误码与请求 ID；HTTP 请求的完成不表示对应后台作业已经完成。

新增管理 HTTP 记录不保存请求正文、查询参数、认证头、原始异常或证据正文。MCP 历史文件只按白名单投影，页面不展示查询正文、查询哈希、会话身份或原文内容。原 MCP `WENJIN_AUDIT_INCLUDE_QUERY=0` 默认策略保持；已有显式开启正文记录的历史文件不会因此自动删除，管理页面仍不返回正文。

MCP 现有审计覆盖 `search_docs` 和原文取件；被丢弃证据的诊断事件不是独立调用。默认 `stdout` 无可读取的历史文件，`off`、文件缺失或不可读时显示具体覆盖限制，不能显示为“没有发生调用”。文件模式需要管理服务与 MCP 指向相同的项目内审计文件；读取当前文件及轮转文件并设资源上限，超出时标明截断。旧记录缺少检索目标时显示未知，不从查询正文猜测。

账号模式下，MCP每次请求验证该用户的个人MCP凭据，并根据稳定资料库/受管文件资源授权过滤检索、目录和原文；已经建立的状态化协议session不会缓存授权结果，凭据撤销或资料库撤权会影响后续请求。旧Bearer模式继续遵循既有 `managed-file-<file_id>` / `managed-files` ACL。账号库启用不会自动转换旧ACL或把历史资料设为公开。

## 资料库发布与评测入口

管理员在“资料库版本”页选择服务器公布的候选索引目标，提交prepare后等待任务完成，再执行validate并按预期revision切换active；需要回退时选择保留版本执行rollback。API入口包括 `GET /api/admin/release-targets`、`POST /api/admin/releases/prepare`、`GET /api/admin/release-jobs/{job_id}`、`POST /api/admin/releases/{release_id}/validate`、`POST /api/admin/libraries/{library_id}/activate` 与 `/rollback`。请求只能选择服务端登记的library、target或release，服务端校验目标资产和模型身份，不接受任意索引路径。

管理员“检索评测”页提供 `gdal_dstalpha_diagnostic_v1`（单题baseline诊断）与 `developer_four_arm_v1`（固定开发题集的 baseline/parent-child/multi-query/MMR 对照）。API为 `GET /api/admin/evaluations/templates`、`POST /api/admin/evaluations`（唯一字段 `experiment_id`）、任务列表/详情/取消/恢复和 `/result`。每条任务绑定固定数据、当前release快照、策略配置、代码与模型资产身份；只在所有case checkpoint及前后资产验证完整时标记completed。四臂需要现有QueryRewriteSettings配置；配置不可用时任务会被拒绝或失败，不会伪报空成功。任务结果和逐题证据仅管理员可读，并且读取时再次检查任务涉及资料库的当前授权。

## 最小代码：文件数组如何进入表格

```js
const response = await fetch("/api/files");
const data = await response.json();
const files = data.files;
```

1. `fetch` 输入同源地址字符串，返回 Promise；`await` 得到浏览器的 `Response` 对象。启用认证时，真实请求还需附加 `Authorization: Bearer ...`。
2. `response.json()` 返回 Promise；`await` 得到普通 JavaScript 对象。例如空库返回 `{ files: [] }`。
3. `data.files` 是数组；表格逐行读取 `display_name`、`status`、`version`、`chunk_count`。实际实现先检查 HTTP 状态再读取数据，并用安全文本节点展示文件名和正文。

业务封装在 `src/wenjin/file_management/admin/app.js`，布局在 `index.html`，样式在 `styles.css`。管理 HTTP 的装配、文件/任务/检索/日志 handler 和静态资源读取分别位于 `src/wenjin/management_http/`；`src/wenjin/file_management/api.py` 是旧导入兼容入口，持久任务查询仍由 `file_management/service.py` 承担。静态文件目前仍随 `wenjin.file_management` 包交付，这是资源位置过渡，不代表 HTTP 实现仍归文件生命周期模块。
